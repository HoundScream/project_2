# Формат сценариев

Каждый файл в этой папке — один пользовательский сценарий: JSON с упорядоченным списком шагов. Формат один и тот же для обоих раннеров:

- `src/scenario_lib` (Rust, HTTP-уровень, быстрый и без браузера) — `cargo test`, либо CLI `scenario-runner`.
- `ui-tests/runner.mjs` (Node/Playwright, реальный Chromium, со скриншотами) — опциональный, тяжёлый слой.

Один сценарий = один файл = одна цельная пользовательская история («зарегистрировался и запустил анализ», «вошёл существующим аккаунтом» и т.д.), а не отдельный тест-кейс на каждый шаг.

## Структура файла

```json
{
  "name": "register_and_free_analysis",
  "description": "Короткое описание сценария для отчётов",
  "vars": { "card_url": "https://..." },
  "steps": [ { "...": "..." } ]
}
```

- `name` — уникальное имя сценария, попадает в отчёт.
- `vars` — необязательные постоянные переменные сценария (например, тестовая ссылка на карточку).
- `steps` — шаги, выполняются по порядку. Если шаг падает, сценарий останавливается сразу (следующие шаги обычно зависят от `capture` предыдущих).

## Шаги

Каждый шаг — один объект с полем `action` и набором применимых полей. Неиспользуемые поля просто игнорируются.

### `action: "navigate"`
Обычный `GET` по `path`.

### `action: "fill_form"`
Отправка формы на `path`: HTTP-раннер шлёт `POST` с телом `fields` напрямую; браузерный раннер находит на странице `<form>`, реально заполняет поля (`page.fill`/`selectOption`) и кликает submit — то есть в точности то, что делает настоящий пользователь. Если несколько полей в `fields` являются `type="hidden"` (страницы вида «несколько кнопок = несколько маленьких форм», как управление подпиской), браузерный раннер сам находит ту форму, где скрытое поле уже равно нужному значению, а не пытается его переписать.

### `action: "wait_for_text"`
Опрашивает `path` (интервал `poll_ms`, таймаут `timeout_ms`) пока видимый текст страницы не будет содержать `text`. Нужен для экранов с фоновой обработкой (например, статус анализа).

## Общие поля-проверки (применимы к любому action)

- `name` — человекочитаемое имя шага для отчёта.
- `expect_status` — ожидаемый HTTP-статус. **Важно:** оба раннера не следуют за редиректами одинаково — HTTP-раннер видит «сырой» `303` до перехода, а настоящий браузер всегда прозрачно следует за редиректом и статус недоступен для наблюдения. Поэтому браузерный раннер игнорирует `expect_status` в диапазоне 3xx (используйте `expect_redirect_contains` — оно работает в обоих раннерах, просто проверяется по-разному: по заголовку `Location` в HTTP-раннере и по финальному `page.url()` в браузерном).
- `expect_redirect_contains` — подстрока, которая должна быть в цели редиректа.
- `expect_text` — список подстрок, которые должны быть видны пользователю (заголовок вкладки + текст страницы, без HTML/CSS).
- `expect_selector` — список CSS-селекторов, каждый должен найти хотя бы один элемент.
- `capture` — `{ "имя_переменной": "текст перед id" }`. Ищет первое вхождение строки-префикса в заголовке `Location` (если это редирект) или в теле/URL страницы и захватывает следующий за ним `[A-Za-z0-9-]+` (формат UUID, используемый везде в приложении). Захваченное значение доступно в следующих шагах как `{{имя_переменной}}`.

## Шаблонные переменные

`{{имя}}` в `path`/`fields`/`expect_text`/`expect_redirect_contains` подставляется из:

- `vars` сценария,
- значений, сохранённых через `capture` в предыдущих шагах,
- генераторов `{{random.full_name}}`, `{{random.email}}`, `{{random.phone}}`, `{{random.telegram}}`, `{{random.password}}`, `{{random.uuid}}` — значение генерируется один раз при первом использовании и повторно используется дальше в том же сценарии (например, чтобы залогиниться тем же email/паролем, которым только что зарегистрировались).

## Как запускать

```bash
# Быстрый слой (нужен запущенный сервер: cargo run в соседнем терминале)
cargo test --test run_scenarios
cargo run --bin scenario-runner -- scenarios/*.json

# Тяжёлый слой с реальным браузером и скриншотами в artifacts/site-screenshots/
GEONETIX_BROWSER_NO_SANDBOX=1 node ui-tests/runner.mjs --screenshots scenarios/*.json
```

По умолчанию оба раннера бьют в `http://127.0.0.1:8080`; переопределяется переменной окружения `GEONETIX_TEST_BASE_URL` (можно указать staging/прод-подобный адрес).

## Как добавить новый сценарий

1. Создать `scenarios/<имя>.json` по формату выше.
2. Rust-раннер подхватит его автоматически (`tests/run_scenarios.rs` перебирает все `*.json` в этой папке).
3. Для браузерного раннера просто передать файл явным аргументом (`node ui-tests/runner.mjs scenarios/<имя>.json`).

# Stage 04.3 - Движок анализа

Date: 2026-05-21

## Goal
- Подключить фоновый движок анализа к модулю 4.2, чтобы статус обновлялся по реальным этапам обработки, а результат автоматически сохранялся в кабинете.

## Input Context

- Related files: src/main.rs, database/init/001_init.sql, deploy/stages/2026-05-21-stage-04-2-analysis-status.md

## Implementation Summary
- Decisions:
  - Анализ запускается фоновым `tokio`-воркером сразу после создания `analysis_request`.
  - Статусы больше не вычисляются по времени открытия страницы: воркер сам обновляет шаг, процент, сообщение и детали этапа в БД.
  - Итог анализа сохраняется в новой таблице `analysis_reports`, а экран 4.2 читает уже сохранённый отчёт.
  - Для совместимости с существующей базой приложение при старте само добавляет недостающие колонки и таблицу отчётов через `ensure_analysis_schema`.
- Changes:
  - src/main.rs: добавлены фоновые этапы движка, обновление статусов анализа, генерация и сохранение отчёта, чтение живого прогресса для экрана 4.2.
  - database/init/001_init.sql: добавлены поля прогресса в `analysis_requests` и таблица `analysis_reports`.

## Validation
- `cargo fmt`: passed (2026-05-21)

- Limitations:

  - Фоновый воркер живёт внутри процесса приложения; для production-очереди позже стоит вынести его в отдельный worker layer.
